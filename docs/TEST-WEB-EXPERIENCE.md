# مواصفات الواجهات التجريبية وتجربة العرض

**الإصدار:** 1.0  
**التاريخ:** 8 أكتوبر 2026  
**المرجع:** [خطة التنفيذ](../DEVELOPMENT-PLAN.md)  
**الحالة:** مواصفات للتطوير والقبول؛ الواجهات لم تُنفذ بعد

## 1. هدف التجربة

الواجهات هي بوابة تقديم المشروع وإثبات جودة التنفيذ. يجب أن يفهم المشاهد غير التقني ما يفعله النظام، ومن يملك الطرد، وما الإجراء التالي، وكيف تتحسن الخدمة والتكلفة، دون قراءة سجلات أو معرفة API.

نستهدف تجربة عربية رسمية، منظمة وسهلة، تبدو كمنتج متكامل. تعكس المؤشرات والخريطة والحالات بيانات الخادم نفسه؛ لا تؤدي الرسوم أو التنسيقات إلى إظهار إنجاز غير حقيقي.

الواجهات تتصل بالمنصة الفعلية في بيئة اختبار. يوجد خادم تطبيق تجريبي يحاكي التطبيق التجاري قبل Tendsy، ويستخدم عقده المتوقع ومفاتيح خاصة بالخادم ومستقبل Webhooks. يمكن تغيير خادم الربط لاحقًا دون تغيير قلب النظام.

## 2. نظام التصميم

### الاتجاه البصري

- لغة أساسية عربية وRTL، مع عزل اتجاه الأرقام والمعرفات والهواتف والمصطلحات الإنجليزية حتى لا تنقلب أو تتداخل.
- لوحة ألوان هادئة: كحلي للنص والتنقل، ولون تركوازي للإجراء الرئيسي، وخلفيات فاتحة محايدة، وألوان دلالية للحالات. تتحدد القيم النهائية في design tokens وتُقاس نسبة التباين.
- خط عربي واضح مرخص ومحلي الاستضافة، مع بديل مناسب. لا يعتمد عرض النص على تحميل CDN خارجي وقت التقديم.
- شبكة مسافات موحدة من مضاعفات 4 و8 بكسل؛ زوايا وظلال وحدود متسقة، مع تجنب كثرة البطاقات والتدرجات والزخارف.
- حجم نص الجسم المفضل 16px؛ يمكن استخدام 14px في الجداول الكثيفة إذا بقي مقروءًا. لا تُصغر البيانات المالية أو أسباب الفشل لإخفاء كثافة الصفحة.
- رسوم وأيقونات من نظام واحد؛ الأيقونة تدعم النص ولا تستبدله عندما يكون معناها غير واضح.
- الإجراء الرئيسي واضح لكل شاشة، والإجراء الخطير منفصل وله تأكيد يشرح الأثر. لا تكون كل الأزرار متساوية في اللون والبروز.
- الحركة محدودة وتخدم انتقال الحالة، مع احترام تقليل الحركة؛ لا توجد حركة مستمرة تشتت العرض أو تستهلك الهاتف.
- اسم المنتج والشعار قابلان للتبديل من إعدادات الهوية. لا يُستخدم شعار Tendsy كهوية للمنصة أو كادعاء عن تصميمه الفعلي.

### مكونات مشتركة

| المكون | السلوك المطلوب |
|---|---|
| هيكل الصفحة | تنقل واضح، عنوان وشرح موجز، وإجراء رئيسي، ومحتوى منظم |
| جدول البيانات | بحث وفلاتر وفرز وتصفح من الخادم، وعرض هاتف مناسب دون فقد الإجراءات |
| بطاقة المؤشر | قيمة ووحدة وفترة ومعنى؛ لا نسبة تغير دون فترة مقارنة |
| شارة الحالة | نص ولون وأيقونة عند الحاجة؛ لا تعتمد على اللون وحده |
| الخط الزمني | حدث ووقت وفاعل أو جهة وفق الصلاحية؛ تمييز المنجز عن المتوقع |
| النموذج | labels ظاهرة، والتحقق بجانب الحقل، وحفظ المدخلات عند فشل الإرسال |
| صفحة التفاصيل | ملخص ثابت وأقسام تشغيل وعهدة وأموال وأحداث بحسب الدور |
| الخريطة | وسيلة شرح لا شرطًا لإكمال المهمة؛ بديل قائمة عند تعذرها |
| التنبيه | سبب واضح وإجراء ممكن؛ toast للأثر القصير، ورسالة ثابتة للمشكلة المستمرة |
| التأكيد | وصف أثر الإلغاء أو إعادة الإسناد أو التسوية مع سبب عند الحاجة |
| البحث والاختيار | يميز المنشأ والوجهة والسعة والوقت، مع عدم إخفاء الخيارات غير المتاحة بلا تفسير |

ينشأ دليل مكونات مصغر باستخدام حالات حقيقية من السيناريوهات، ويُستخدم في جميع الواجهات بدل تصميم كل شاشة بصورة مستقلة.

## 3. خريطة الواجهات

### A — بوابة العرض

- تعريف موجز: منصة لوجستية تربط التطبيقات بشبكة تنفيذ مشتركة.
- وصول إلى السيناريوهات وحسابات العرض المخولة؛ لا تبديل صلاحيات بمجرد تغيير خيار من المتصفح.
- ملخص الحالة التشغيلية والسيناريو الحالي ووسم «بيئة تجريبية» واضح وغير مزعج.
- صفحة نتائج تشرح تكلفة التنفيذ ووقت الخدمة والمشكلات التي عولجت، مع مصدر القياس.
- وصول إعادة الضبط محدود للمختبر، ويفصل عن إجراءات المستخدم المعتادة.

**معيار القبول:** يستطيع المشاهد معرفة هدف المشروع وبدء رحلة عرض خلال دقيقة دون شرح تقني.

### B — التطبيق التجاري التجريبي

- إنشاء طلب بمصدر واضح: طرد جاهز أو منتجات من مخزون تجريبي.
- اختيار الوجهة والخدمة وعرض السعر والعملة والموعد وشروط وصلاحية العرض.
- تأكيد الطلب وتتبع حالته وشحناته، وإلغاء أو إرجاع وفق قواعد المرحلة.
- الطلب متعدد المتاجر يعرض كل متجر وشحناته وخيار تسليمه منفصلًا، مع ملخص إجمالي واضح.
- لا يطلب عنوان منزل عند اقتصار الطلب على الاستلام من نقاط مشاركة؛ يطلب فقط بيانات الخدمة اللازمة.
- تغير العرض أو انتهاء صلاحيته يعرض سببًا ويطلب اختيارًا واضحًا، دون تغيير السعر أو الوجهة بصمت.

**معيار القبول:** يرسل الطلب عبر خادم التطبيق التجريبي إلى API، وتعود تحديثاته من Webhooks أو الاستعلام وفق العقد؛ لا تكتفى محاكاة الحالة في المتصفح.

### C — لوحة إدارة العمليات

- مؤشرات للشحنات النشطة والمتأخرة والمتعثرة والتحصيل غير المسوى، محسوبة من البيانات وذات تعريف واضح.
- قائمة شحنات بفلاتر الدور والمنطقة والخدمة والحالة والوقت مع حفظ حالة التصفح عند العودة.
- تفاصيل شحنة تضم ملخصًا وخطًا زمنيًا ومراحل النقل والعهدة والإثباتات والإجراء التالي.
- إدارة الشبكة: شركاء ومواقع ومناطق وسعات وساعات عمل ومسارات ومركبات وأهلية.
- الإسناد: المرشحون والتوفر والسعة والموعد المتوقع وكلفة إدخال المهمة في الجولة وأسباب الاختيار.
- الاستثناءات: سبب ومسؤول ومهلة وإجراء، مع إمكانية فتح مطالبة أو إرجاع أو إعادة محاولة.
- المالية: مبلغ التحصيل وحائزه ومراحل التسوية والفروق، دون تسمية المستحقات أموالًا محصلة.

**معيار القبول:** يعرف المشغل الجهة الحائزة للطرد، والإجراء المطلوب، وأثره، دون التنقل بين شاشات متعارضة.

### D — المتجر والمستودع ونقطة الاستلام

- صلاحيات وبيانات بحسب الدور؛ المتجر لا يرى المخزون أو الطلبات المالية لمتجر آخر.
- المتجر: طلبات التنفيذ والجاهزية وإجراءات التسليم للشريك والمستحقات المسموح بها.
- المستودع: متاح ومحجوز وتجهيز وقيد نقل وتالف، مع حركات واستلام وجرد معلل.
- انتقال المخزون بين موقعين يظهر الإرسال والاستلام والفروق؛ تعديل الرقم وحده ليس نقلًا.
- نقطة الاستلام: قائمة المتوقع والوارد فعليًا والجاهز للعميل والمنتهي أو المعاد، مع استلام الطرد ثم تسليم العميل كإجراءين مختلفين.
- رمز الاستلام والتحصيل في شاشة قصيرة توضح المطلوب والنتيجة دون كشف الرمز في القوائم.

**معيار القبول:** تسجل كل خطوة العهدة الصحيحة، ويُرفض جمع العميل قبل الاستلام الفعلي أو باستخدام رمز منتهي أو مستخدم.

### E — واجهة المندوب للهاتف

- قائمة مهام مرتبة وملخص الجولة ونقاط الاستلام والتسليم، دون لوحة مزدحمة.
- زر إجراء رئيسي كبير لكل مرحلة: قبول، أو استلام، أو وصول، أو تسليم، أو تسجيل فشل.
- ظهور متطلبات المركبة والفحص والأهلية عند انطباقها، قبل السماح بالاستلام.
- تفاصيل الوجهة والمبلغ المطلوب والتعليمات اللازمة فقط؛ لا يعرض تاريخ العميل غير المرتبط بالمهمة.
- مشاركة الموقع اختيارية بصلاحية وبيان حالة آخر تحديث، مع معالجة رفض الإذن أو قدم الموقع.
- عند انقطاع الاتصال: مؤشر ثابت، وحالة «بانتظار المزامنة»، وقائمة محاولات يمكن مراجعتها؛ لا يوصف الحدث بأنه مؤكد قبل قبول الخادم.
- فتح الملاحة ممكن، لكن الخريطة ليست شرطًا لتسجيل الاستثناء أو الوصول إلى تفاصيل المهمة.

**معيار القبول:** تعمل الرحلة على عرض 360px، ويمكن تنفيذها بيد واحدة مع نص وأزرار واضحة، دون تمرير أفقي للصفحة.

### F — تتبع العميل

- حالة مفهومة، وموعد تقديري عندما تدعمه البيانات، وآخر تحديث، وخط زمني مبسط.
- وجهة الاستلام وساعاتها عند الخدمة، وإجراءات التواصل المسموح بها.
- تمييز الوصول إلى نقطة الاستلام عن جاهزية الطرد لاستلام العميل وعن جمعه فعليًا.
- عدم عرض موقع قديم كأنه لحظي؛ اختفاء التتبع عند توقف المشاركة أو انتهاء التعيين.
- عدم عرض الهاتف أو الملاحظات الخاصة أو عنوان المنزل التفصيلي عبر رابط عام.
- حالة واضحة للرابط المنتهي أو الملغى أو الشحنة التي لا يملك الزائر حق عرضها.

**معيار القبول:** يفهم العميل أين وصلت العملية وما المطلوب منه دون كشف بيانات خاصة أو إعطاء موعد غير موثوق.

### G — مختبر التكامل والتحسين

هذه واجهة للمختبر فقط؛ لا تظهر التفاصيل التقنية ضمن رحلة العميل أو المندوب.

- طلبات وأحداث منقحة من الأسرار، ومراجع ارتباط، ومحاولات Webhooks، ومزامنة التطبيق.
- إعادة إرسال الطلب نفسه، وتأخير الحدث، وفشل مستقبل Webhook، ثم استعادته والمطابقة.
- مقارنة بحث واسع وPostGIS وH3 على البيانات نفسها مع إعدادات كل تجربة.
- عرض عدد المرشحين ووقت البحث وحسابات الطرق والتكلفة وفقدان أفضل مرشح وحدود الحل.
- تبديل عرض الخطة المرجعية والمحسنة مع توضيح الحالات التي تتساويان فيها أو لا يتحقق فيها وفر.
- تعطل مزود الطرق أو انتهاء مهلة الحل يؤدي إلى نتيجة صريحة وخطة بديلة، لا شاشة نجاح وهمية.

**معيار القبول:** يمكن إثبات سلامة التكرار والتعافي وقيمة التحسين دون تعديل جداول يدويًا.

## 4. سيناريوهات العرض المرجعية

جميع الشخصيات والأرقام المالية والمواقع وبيانات الطرق التجريبية تُعرف كبيانات اصطناعية. يمكن استخدام أسماء مدن لتوضيح التوسع، دون الادعاء أن الشبكة تعمل فيها فعليًا.

| الرمز | القصة | ما يراه المشاهد | الدليل المطلوب |
|---|---|---|---|
| DMO01 | متجر ينشئ طردًا محليًا ويسلمه مندوب للعميل | طلب وخيارات وإسناد وعهدة وتتبع وتسليم | أحداث متسقة في التطبيق والخادم وإثبات |
| DMO02 | منتجات من مستودع مع تنافس على آخر كمية | متاح ومحجوز وتجهيز، ورفض الحجز الزائد | كمية صحيحة تحت التزامن وسجل الحجز |
| DMO03 | نقطة استلام مع رمز وCOD | استلام الموقع ثم جمع العميل وتسجيل المال | رمز يستخدم مرة واحدة وتسوية مستقلة |
| DMO04 | نقل بين مدينتين عبر مركزين | مراحل ومسؤولون ومواعيد تحويل وبيان شحن | عهود متسلسلة وسعات وجداول سليمة |
| DMO05 | تعذر التسليم ثم إرجاع | سبب ومحاولة أو إرجاع وفحص مستودع | عدم إعادة المتاح للبيع قبل الفحص |
| DMO06 | طلب مكرر وWebhook فاشل ثم تعافٍ | شحنة واحدة وإشعار معاد ونتيجة متطابقة | لا أثر تشغيلي أو مالي مكرر |
| DMO07 | مندوب قريب غير ملائم وآخر يلائم الجولة | سبب الاستبعاد ومقارنة التكلفة والموعد | اختيار مفحوص وبيانات مقارنة قابلة لإعادة الحساب |
| DMO08 | حدود خلايا ومنطقة قليلة الموارد وموقع قديم | توسع البحث واستبعاد الموقع القديم | قياس جودة القائمة واختيار سليـم أو عدم إمكانية معلل |

### تسلسل تقديم مقترح من 10 إلى 15 دقيقة

1. تعريف المنصة وعلاقتها بالتطبيق التجاري من بوابة العرض.
2. رحلة DMO01 بين المتجر والمشغل والمندوب والعميل.
3. مقارنة الإسناد DMO07 وتفسير القيمة بلغة الوقت والتكلفة.
4. عرض نقطة الاستلام والمال DMO03 لإثبات اكتمال الدورة.
5. إظهار مسار النقل بين المدن ثم استثناء الإرجاع دون تنفيذ جميع التفاصيل أمام الجمهور.
6. إثبات عدم التكرار والتعافي DMO06 وعرض النتائج المقاسة.

المدة تنظيم للعرض فقط، وليست تقديرًا لزمن التشغيل الفعلي. لا يُستخدم زر يقفز إلى الإكمال متجاوزًا القواعد؛ يمكن تحميل سيناريو محفوظ أو حساب مختلف بصلاحية معلنة لتقليل زمن التقديم.

## 5. حالات الواجهة التي لا يجوز إغفالها

- تحميل أولي وتحميل إجراء وبيانات جاهزة وحفظ قيد الانتظار.
- فراغ حقيقي مع إجراء مناسب، وفراغ بسبب الفلاتر مع إمكانية مسحها.
- خطأ تحقق، وخطأ خدمة، ومهلة، ورفض صلاحية، ورابط منتهٍ، وتعارض إصدار.
- انقطاع اتصال أو فشل خريطة أو رفض إذن الموقع أو عدم وجود طريق أو مندوب مؤهل.
- بيانات قديمة يظهر عمرها؛ وفشل تحديث لا يمسح آخر بيانات صحيحة دون تفسير.
- إجراء مكرر أو زر مضغوط عدة مرات لا ينتج عدة عمليات؛ لا يعتمد المنع على تعطيل الزر وحده.
- العمليات الطويلة لها حالة تقدم وإلغاء عندما يكون آمنًا، ولا تُجمد الصفحة.
- رسائل خطأ عربية مفهومة؛ يظهر مرجع دعم بدل stack trace أو تفاصيل خادم.

## 6. إمكانية الوصول والاستجابة

الهدف WCAG 2.2 AA في الشاشات الأساسية، مع مراجعة يدوية؛ الفحص الآلي وحده لا يثبت المطابقة. المرجع [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

- تشغيل بلوحة المفاتيح وترتيب تركيز منطقي وحدود تركيز مرئية وإدارة صحيحة للحوارات.
- تباين لا يقل عن 4.5:1 للنص المعتاد و3:1 للنص الكبير، وفحص تباين عناصر التحكم المناسبة.
- labels وأسماء وصول للأزرار والأيقونات ورسائل التحقق، مع إعلان الحالة المهمة لقارئ الشاشة.
- تمييز الحالات بالنص إضافة إلى اللون؛ احترام التكبير وتقليل الحركة.
- أزرار المندوب تستهدف 44×44px على الأقل كمعيار تصميم عملي.
- مراجعة أحجام 360 و390 و768 و1280 و1440px، واتجاه RTL والحقول LTR والتواريخ والمبالغ الطويلة.
- الجداول على الهاتف تتحول إلى عرض مناسب أو تمرير داخل الجدول عند الحاجة؛ لا ينكسر هيكل الصفحة كله.

## 7. القبول البصري والوظيفي

### قبل التنفيذ الكامل

- [ ] خريطة تنقل وتسلسل رحلة ووصف إجراء رئيسي لكل شاشة.
- [ ] نموذج بصري للوحة التشغيل وتفاصيل الشحنة وواجهة المندوب وبوابة العرض.
- [ ] tokens للخط واللون والمسافات والحالات، ومكونات تستخدمهـا جميع الشاشات.
- [ ] ملاحظات المراجعة مسجلة ومحلولة قبل تعميم التصميم.

### قبل عرض النتيجة

- [ ] كل زر ظاهر يعمل أو يعرض عدم التوفر وسببه؛ لا توجد أزرار صامتة أو روابط معطلة.
- [ ] السيناريوهات DMO01–DMO08 قابلة للتكرار من بيانات معروفة.
- [ ] المؤشرات والحالات والتتبع والأموال متطابقة مع API وقاعدة الاختبار.
- [ ] لا قص نصوص أو تداخل أو قفز تخطيط ملحوظ أو أحجام غير متسقة.
- [ ] مراجعة كل شاشة وحالة رئيسية على الحاسوب والهاتف، مع لقطات وملاحظات.
- [ ] نجاح اختبارات رحلة المتجر والمندوب ونقطة الاستلام، مع تعارض وتكرار وفشل.
- [ ] نجاح مراجعة لوحة المفاتيح والتباين والتحقق ومقروئية العربية.
- [ ] ظهور حدود المحاكاة والبيانات التجريبية، دون ادعاء رسائل أو تتبع أو وفر حقيقي.
- [ ] تشغيل محلي موثق، واستقلال سيناريو العرض الأساسي عن مزود خارجي غير متاح.
- [ ] إعادة الضبط محدودة لبيانات السيناريو، ولا تمس جلسة عرض أو بيانات أخرى بلا نطاق واضح.
- [ ] لا بيانات شخصية حقيقية أو أموال فعلية أو مفاتيح في المتصفح أو اللقطات.
- [ ] تقرير الأداء يحدد الموارد وحجم البيانات والقياس، ولا يكتفي بتقييم شكلي.

## 8. مخرجات التنفيذ

واجهات متصلة بالنظام، ودليل مكونات، وبيانات بذر، وخادم تطبيق تجريبي، ومكتبة سيناريوهات، ودليل تشغيل وإعادة ضبط، ولقطات مراجعة، وتقرير اختبارات وأداء، ومسار تقديم جاهز. تُضاف الملفات التنفيذية ومسارات تشغيلها عند بنائها؛ لا توثق هذه المواصفات مسارات وهمية لبرامج لم تُنشأ.

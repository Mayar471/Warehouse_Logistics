# استعادة الإقرارات المالية بعد إغلاق الصفحة

التاريخ: 12 أكتوبر 2026. شريحة محلية للوحتي «التحصيل وعهدة النقد» و«مستحقات المتاجر». لا تغير قواعد التحصيل أو الصرف أو القيود، ولا تعني استعادة جميع أوامر الشحن والمخزون أو تشغيلًا دون اتصال.

## رحلة المستخدم

قبل إرسال إقرار من اللوحتين، يُحفظ الحساب والمسار ومحتوى الطلب الأصلي ومفتاح منع التكرار ووصف الإقرار ووقت إعداده. فشل حفظ هذا السجل يوقف الإرسال؛ لا يُعلن حفظ مالي على الخادم دون رد منه.

إذا انقطع الرد، تبقى الحقول مجمدة ويمكن إعادة الإقرار نفسه داخل النموذج الحالي. عند إعادة تحميل الصفحة أو إغلاق التبويب وفتح العرض مجددًا في المتصفح نفسه، يظهر تنبيه في أعلى صفحة الحساب يقود إلى بطاقة الاستعادة، وتظهر البطاقة قبل الأرصدة في اللوحتين. الحساب الآخر لا يعرض هذا الإقرار ولا يستطيع متابعة تنفيذه باسمه.

لا ترسل الصفحة المستعادة الطلب تلقائيًا. توفر البطاقة اختيارين:

1. «فحص نتيجة الحفظ»: قراءة من الخادم تبين هل سُجل الإقرار نفسه فعلًا. إذا كان مسجلًا، ينتهي سجل الاستعادة وتتحدث القراءة دون إعادة أي حركة مالية.
2. «إعادة إرسال الإقرار المحفوظ»: تتطلب مراجعة صريحة للمرجع والسبب والمبلغ الموجود في الإقرار، وتعيد المسار والمحتوى والمفتاح أنفسها. مفتاح منع التكرار على الخادم يعيد النتيجة السابقة إذا حُفظ الطلب، أو ينفذه مرة واحدة إذا لم يُحفظ وكانت شروطه لا تزال صالحة.

عدم العثور على نتيجة لا يثبت وحده أن طلبًا سابقًا متأخرًا لن يصل؛ لذلك لا ينشأ مفتاح جديد ولا محتوى جديد عند إعادة الإقرار. التعارض مع محتوى آخر يحتفظ بالسجل ويوقف الإرسال من البطاقة حتى التحقيق. رفض أمر قديم بسبب إصدار أو حالة تغيرت ينعكس برسالة ظاهرة وقراءة جديدة؛ لا يتوارى الرفض عند إنهاء سجل الاستعادة.

## الحماية والحدود

يوجد إقرار مالي محفوظ واحد لكل حساب في المتصفح، يشترك فيه التحصيل والصرف. توقف اللوحتان الإقرارات الجديدة حتى متابعة نتيجته؛ البيانات والسجل المالي يبقيان قابلين للقراءة. لا يؤثر ذلك على أوامر الشحن أو المخزون الأخرى.

Web Locks يحمي إعداد الإقرار وإرساله وفحص نتيجته وإنهاء سجله من تداخل صفحات المتصفح للحساب نفسه. إذا كانت هناك متابعة جارية في صفحة أخرى، تُرفض المحاولة الجديدة مع الحفاظ على الإقرار. منع التكرار والإصدار وقيود الأرصدة على الخادم تبقى الحماية الأساسية عند التعامل من متصفحات مستقلة.

السجل مرتبط بمعرف الحساب ويُتحقق من شكله وحدوده عند القراءة. لا يسمح بمسار خارجي أو API غير مالي أو إجراء غير معروف أو حقول غير معتمدة أو مبلغ غير صحيح. سجل غير صالح أو غير قابل للقراءة يمنع إقرارات جديدة؛ لا يُمسح تلقائيًا ولا يُرسل محتواه. لا يُستبدل سجل غير محسوم بإقرار آخر، ولا ينتهي لمجرد مرور الوقت.

تضيف الواجهة x-financial-actor إلى الإرسال والفحص. يطابقه الخادم بالحساب الفعلي من الجلسة في الطلب نفسه؛ تغير الجلسة في صفحة أخرى يمنع تنفيذ الأمر باسم حساب مختلف. الحقل ليس مصادقة أو تصريحًا إضافيًا؛ الصلاحيات والملكية المعتادة تبقى مطلوبة. الإقرارات السابقة أو تطبيقات API التي لا ترسل هذا الرأس تبقى خاضعة لصلاحيات الجلسة نفسها دون تغيير عقدها السابق.

فشل الشبكة أو رد 5xx أو فقد المصادقة أو اختلاف الحساب أو تعارض مفتاح منع التكرار يحتفظ بسجل الاستعادة. رد رفض مؤكد آخر مثل إصدار قديم أو مبلغ مرفوض ينهي سجل الإقرار المرفوض ويعرض السبب. انتهاء سجل الإقرار بعد رد ناجح أو فحص committed لا يعدل القيد أو الحالة الأصلية؛ ينهي المتابعة في المتصفح فقط.

السجل محفوظ في localStorage ومحدد بهذا المتصفح وأصله وحسابه. يتضمن مرجعًا وسببًا ومبالغ الإقرار، ولا يخزن رمز الجلسة أو مفتاح التطبيق أو بيانات اتصال الخادم. عزل عرضه بين الحسابات ليس تشفيرًا للبيانات على الجهاز. مسح بيانات المتصفح أو الانتقال إلى جهاز أو أصل آخر لا ينقل السجل. التحكم الإنتاجي بالبيانات والأجهزة المشتركة واستعادة سجل تالف ومسار تحقيق التعارض ما زال يحتاج سياسة وتنفيذًا إضافيين.

## فحص النتيجة على الخادم

POST /api/financial-commands/status إجراء قراءة موثق بالجلسة، يقبل url وbody الأصلي كسلسلة JSON وkey فقط. لا يكتب سجل منع تكرار أو قيدًا أو حدثًا، ولا ينفذ الأمر المحفوظ.

```json
{"url":"/api/payouts","body":"{\"shipmentId\":\"معرف UUID\",\"expectedCollectionVersion\":3,\"reference\":\"حجز 101\",\"reason\":\"إعداد صرف المستحق\"}","key":"مفتاح الإقرار الأصلي"}
```

النتيجة state:

- committed: سجل الحساب والمسار والمفتاح موجود وبصمة المحتوى المطبع تطابق الإقرار.
- unknown: لا توجد نتيجة لهذا الحساب والمسار والمفتاح وقت القراءة.
- conflict: المفتاح في نطاق الحساب والمسار نفسه مسجل بمحتوى آخر، دون كشف ذلك المحتوى.

المسارات المقبولة: /api/payouts و/api/payouts/:id/actions و/api/cash/:id/actions. يعيد ترتيب مفاتيح الجسم وتقليم المرجع والسبب كما في عقود الإقرارات الحالية قبل مقارنة SHA-256 للبصمة. لا يكشف نتائج حساب آخر، ولا يعيد جسم الإقرار الأصلي أو أي أسرار. القراءة تستخدم بوابة المعاملات نفسها لتجنب قراءة نتيجة أثناء ترحيل حركة غير مكتملة.

لا ترحيل مخطط جديد لهذه الشريحة. تستفيد من idempotency الموجود، وتبقى قاعدة العرض عند الإصدار 17. أثر التشغيل محلي: سجل صغير واحد لكل حساب في المتصفح، وقراءة مفهرسة بالنطاق والمفتاح عند طلب الفحص؛ لا عامل مراقبة أو polling مالي دائم.

## أدلة التحقق

tests/financial-journal.test.ts: حدود المسار والمحتوى والحساب، وحفظ المحتوى الأصلي، وعدم استبدال إقرار غير محسوم، وعزل سجلات الحسابات، وبقاء السجل التالف ورفض الإرسال عند تعذر الحفظ.

tests/financial-recovery.test.ts: committed وunknown وconflict، وتطبيع المحتوى، وعدم كشف حساب آخر أو إضافة قيد أو نتيجة منع تكرار أثناء الفحص، وحماية تغير الحساب في التحصيل والصرف، ونطاق إنشاء الصرف وإجراءاته، واستمرار نتيجة الأمر بعد إعادة تشغيل قاعدة البيانات.

scripts/financial-recovery-check.ts: فقد رد الحجز بعد الحفظ ثم إغلاق التبويب وفتح آخر، وإخفاء الإقرار عند تبديل الحساب وإظهاره للحساب الأصلي، وفحص النتيجة دون إعادة POST للحجز، وفقد طلب الخروج قبل وصوله ثم إعادته بالمفتاح نفسه بعد المراجعة، ومنع تداخل صفحتين أثناء إقرار المتجر، ومعرفة وصوله دون تكراره، ورفض إقرار قديم برسالة ظاهرة، وحماية سجل تالف، ومراجعة 1440 و390 و360px. قواعد الاختبار وبيانات المتصفح معزولة عن العرض الدائم.

استعادة تحصيل النقد المرافق لتسليم الشحنة، وأوامر إنشاء الشحنات والمخزون والنقل، وسجل تحقيق قابل للنقل بين الأجهزة، والعمل دون اتصال مع مزامنة لاحقة، واستعادة إعدادات المتصفح الممسوحة، وحل التعارض أو تلف السجل بإجراء إداري مدقق، والمالية والمصادقة الإنتاجية تبقى لاحقة.

نتيجة التحقق النهائية: 119 اختبارًا ناجحًا للمشروع بالكامل، مع نجاح البناء وفحص التنسيق ورحلة الاستعادة النهائية، ورحلتي فروق رجوع الحوالة واسترداد الدفعات السابقتين. روجعت لقطتا الهاتف والحاسوب بصريًا دون تجاوز أفقي. التقرير الكامل في artifacts/financial-recovery-test-results.txt.

أُعيد تشغيل العرض المحلي دون ترحيل جديد. نجحت قراءة التحصيل والصرف مع مطابقة سليمة ورصيد صفري وعدم وجود دفعات اختبارية. فحص إقرار غير مرسل يعيد unknown دون إنشاء قيد أو أمر؛ بيانات اختبارات الاستعادة بقيت معزولة عن القاعدة الدائمة.

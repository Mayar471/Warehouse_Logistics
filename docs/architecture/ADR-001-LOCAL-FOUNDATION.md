# ADR 001 أساس الشريحة البرمجية الأولى

**التاريخ:** 8 أكتوبر 2026  
**الحالة:** مطبق للشريحة التجريبية الأولى

## القرار

واجهة React وTypeScript ومكونات Lucide وخط Noto Sans Arabic محلي، وخادم Fastify مستقل بعقد JSON، وقاعدة PostgreSQL مضمّنة باستخدام PGlite. الإصدارات المثبتة مسجلة في package-lock.json.

لم توجد ملفات برمجية سابقة. Docker متوفر كأداة لكن خدمته غير مشغلة في البيئة الحالية؛ لذلك استخدمنا PostgreSQL مضمّنًا لتقديم تجربة دائمة البيانات وقابلة للتشغيل دون إعداد خادم منفصل. PGlite تشغيل محلي للتجربة، وليس بديلًا معماريًا لخادم PostgreSQL متعدد العمليات عند الإنتاج.

## حدود التطبيق

- خادم محلي واحد مرتبط بـ127.0.0.1 ويقبل وضع demo فقط.
- حسابات عرض مخصصة: مشغل ومتجران ومندوبان. يمنح مدخل العرض جلسة لحساب معروف ضمن البيئة المحلية؛ لا يمثل تسجيل دخول إنتاجيًا ولا يتيح صلاحيات خارج البيئة التجريبية.
- الجلسات عشوائية محفوظة ببصمتها في الذاكرة وتنتهي بعد ثماني ساعات؛ إعادة تشغيل الخادم تتطلب جلسة جديدة.
- مفاتيح التطبيق والتوقيع مولدة في `.local/secrets.json` المستبعد من التتبع؛ لا تصل إلى حزمة المتصفح.
- المخزون وCOD والعمولات ونقاط الاستلام والنقل بين المدن والتحسين وH3 خارج تنفيذ هذه الشريحة، وتبقى موثقة في الخطة.
- أسعار وعناوين وأسماء العرض اصطناعية. تأكيد التسليم إقرار من حساب المندوب، وليس إثباتًا مستقلًا برمز العميل؛ الواجهة تصرح بذلك.
- واجهة الشبكة تعرض مواقع ومندوبين موجودين في قاعدة التجربة؛ إدارة تسجيلهم وتفعيلهم ليست مكتملة بعد.
- القائمة مقيدة بآخر 100 شحنة؛ تصفح المجموعات الكبيرة وإحصاءات جميع السجلات غير منفذين بعد، والمؤشرات تُسمى وفق بيانات العرض المتاحة.

## حدود المعاملات والتكامل

إنشاء الشحنة واستهلاك العرض وكتابة تاريخها وحدث outbox وحفظ نتيجة منع التكرار ضمن معاملة واحدة. انتقال الحالة وتاريخها وحدثها ونتيجة الأمر كذلك.

PGlite وتقييد الكتابة عبر transaction gate يمنعان تداخل الكتابات داخل هذه العملية. الانتقال إلى PostgreSQL خادمي يتطلب أقفال صفوف أو تحديثات مشروطة ومعاملات واختبارات متعددة العمليات. لا يجوز استخدام قفل الذاكرة وحده في نشر متعدد الخوادم.

بوابة التطبيق التجريبي BFF وحدة داخل الخادم تستدعي عقد التطبيق عبر Fastify inject؛ لا تقرأ قاعدة البيانات لتنفيذ الطلب بدل API. مستقبل Webhooks وحدة ذات endpoint مستقل؛ عامل outbox يرسل إليه HTTP محليًا مع توقيع ووقت ومهلة.

الوجهة ثابتة ولا يُقبل URL خارجي في هذه الشريحة. الفشل يعاد بتراجع زمني لثماني محاولات ثم يبقى ظاهرًا كفشل نهائي. الواجهة تستطيع إعادة محاولة المعلق؛ إعادة تشغيل الفشل النهائي بسياسة مدققة ومطابقة شاملة مؤجلة.

المستقبل يمنع تكرار الحدث ويرفض التوقيع والوقت غير الصالح، ولا يرجع projection إلى إصدار أقدم. لا يُدعى تسليم الشبكة exactly-once؛ منع تكرار الأثر مطبق في المستقبل.

بيانات outbox الحالية معرفات وحالات فقط، دون أسماء وعناوين أو محتوى إشعارات حساس. تشفير payload حساس ومدد احتفاظ وإزالة تحدد عند إضافة هذه البيانات.

## ما يلزم قبل تشغيل فعلي

مصادقة وحسابات فعلية وإدارة صلاحيات كاملة، وخادم PostgreSQL واختبارات تنافس متعددة العمليات، وسياسات إثبات التسليم والتحصيل، وتسجيل الشركاء والأهلية والجداول، والترحيلات والنشر والنسخ والاستعادة، ومراقبة وسجل قرار تكامل Tendsy، وإغلاق بوابات الجودة المناسبة للخدمات المفعلة.

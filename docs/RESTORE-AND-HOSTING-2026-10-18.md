المسار المقترح لتجاوز قيد البناء: بناء صورة تشغيل مسبقًا على GitHub Actions، ثم نشرها على Render بوضع image-backed دون إعادة بناء هناك. [Render يدعم الصور الجاهزة](https://render.com/docs/deploying-an-image)، و[GitHub يوضح مجانية مشغلات Actions القياسية للمستودعات العامة](https://docs.github.com/en/billing/concepts/product-billing/github-actions). المستودع الحالي عام، لكن إعداد صورة التشغيل والفحص الفعلي للذاكرة والنشر لم يُنجز بعد؛ لا نعتبر مجرد إضافة Dockerfile دليل تشغيل.

الاقتراح: خدمة Node واحدة على Render وقاعدة PostgreSQL مستقلة على Neon. [Render يوضح حدود الخطة المجانية](https://render.com/docs/free)، ومنها السكون والقرص المؤقت، و[قاعدة PostgreSQL المجانية لديه تنتهي بعد 30 يومًا](https://render.com/changelog/free-postgresql-instances-now-expire-after-30-days-previously-90). [خطة Neon المجانية](https://neon.com/blog/neon-free-plan-1-gb-per-project) مناسبة لبدء قاعدة عرض ضمن حدودها الحالية؛ تُراجع الحدود عند الإنشاء.

قبل الرفع نحتاج، بالترتيب:

1. تثبيت نجاح الاستعادة محليًا وتوثيق نتيجتها في Git.
2. تحديد حساب قاعدة البيانات المجانية وتهيئة قاعدة مستقلة للعرض؛ لا ننسخ إليها بيانات المستخدم أو أسرار الجهاز.

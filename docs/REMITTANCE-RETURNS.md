# تصحيح حوالة التحصيل برجوع النقد إلى محصله

التاريخ: 12 أكتوبر 2026. مسار محلي تجريبي يكمل [التحصيل وعهدة النقد](./CASH-COLLECTION.md) والصرف والاسترداد، ولا يمثل رد أموال العميل أو محاسبة إنتاجية.

أُضيف لاحقًا [توثيق فرق نقد الرجوع](./REMITTANCE-RETURN-DIFFERENCES.md) بترحيل 17. توثيق الفرق لا يغير العهدة ولا يسجل وصولًا جزئيًا؛ إقرارات الرجوع الأساسية تبقى كما هي.

## نطاق التصحيح

تصحيح كامل حوالة استلمتها العمليات، بإعادة النقد إلى المحصل الأصلي نفسه: مندوب توصيل منزلي أو حساب نقطة الاستلام الذي سجل التحصيل. يبقى تحصيل العميل وتسليم الطرد والمخزون وإثبات التسليم كما هي، وتبقى قيمة البضائع ورسوم التوصيل ومستحق المتجر دون تغيير. لا يُعاد تنفيذ تسليم العميل أو تحصيله.

المبلغ لا يكون مرتبطًا بحجز أو خروج أو استلام دفعة متجر فعال. يجب إلغاء حجز الصرف قبل الخروج، أو إعادة كامل نقد الصرف عبر مساره المستقل أولًا. حتى إقرار المتجر بطلب رد دفعة لا يكفي: يلزم وصولها إلى العمليات قبل رجوع حوالة المحصل. تتوقف أهلية حجز صرف جديد طوال طلب الرجوع وعهدة الرجوع.

## الإقرارات والعهدة

1. العمليات تطلب رجوع الحوالة بمرجع وسبب وكامل مبلغها وعملتها. لا يخرج النقد ولا تتغير القيود؛ الطلب يوقف الصرف من المصدر. يمكن إلغاء هذا الطلب قبل خروج النقد، مع حفظ التاريخ.
2. العمليات تقر تسليم النقد المرتجع فعليًا إلى المحصل الأصلي. قيد remittance_return_release يخفض operations_cash ويزيد remittance_return_transit. يظل المحصل غير مقر بالوصول، ولا تظهر الأموال في عهدته بعد. لا يمكن إلغاء الرجوع بعد الخروج أو إنهاؤه تلقائيًا.
3. المحصل الأصلي وحده يقر وصول كامل النقد بالعملة نفسها، بإقرار مستقل. لا تستطيع العمليات أو متجر أو محصل آخر تأكيد ذلك عنه. المبلغ الجزئي أو المختلف مرفوض وتبقى عهدة الرجوع مفتوحة.
4. عكس remittance الأصلي بقيد remittance_reverse، وعكس قيد الخروج المرتجع بقيد remittance_return_restore، يحدثان معًا في معاملة واحدة. الأثر الصافي عند الإقرار: إزالة remittance_return_transit وزيادة holder للمحصل الأصلي؛ تبقى خزينة العمليات صفرًا لهذه الحوالة منذ خروجها. تصبح حالة التحصيل collected وتعود العهدة إلى المحصل.
5. تستطيع العمليات استلام كامل العهدة لاحقًا بحوالة جديدة ورقم دورة جديد، ثم يصبح المصدر قابلًا لصرف مستحق المتجر. لا تتكرر حركة collection أو إثبات العميل أو أي حركة مخزون.

## العقد والحماية

POST /api/cash/:id/actions مع idempotency-key وexpectedVersion من عهدة التحصيل، وamountMinor كامل وcurrency=SYP وreference وreason:

```json
{"action":"return_request","expectedVersion":3,"amountMinor":22000000,"currency":"SYP","reference":"محضر رجوع 101","reason":"إعادة كامل الحوالة إلى محصلها الأصلي"}
```

الإجراءات: return_request وreturn_release وreturn_cancel للعمليات فقط، وreturn_confirm للمحصل الأصلي فقط بعد الخروج. receive وreport_difference السابقان يبقيان للعمليات. الحساب غير المرتبط لا يستطيع تأكيد حوالة غيره أو قراءة حالاتها خارج نطاقه. الإصدارات القديمة والحقول غير المعروفة والعملات والمبالغ المختلفة مرفوضة.

الطلب والنقد المرتجع مرتبطان بقيد حوالة محدد وشحنتها، وبالمحصل والمبلغ والعملة الأصليين. يوجد طلب رجوع فعال واحد لكل مصدر وقيد فريد يمنع عكس حوالة أصلية مرتين. يمكن إعادة الطلب الملغى قبل الخروج، ولا يمكن إعادة الطلب المؤكد للأصل نفسه.

ترحيل 16 يضيف سجل cash_remittance_returns، وعدد الحوالات في cash_obligations، ورقم الدورة في cash_journals. الحوالة القديمة الوحيدة تُرقم 1 دون تغيير مبالغ أو تفاصيل أي قيد مغلق؛ حقول الربط الجديدة تُملأ داخل الترحيل الذري مع تعطيل مؤقت ومحدد لحارس تعديل رأس القيد ثم إعادته. حماية المبالغ والتفاصيل تبقى بعد الترحيل، ولا يضيف الترحيل نقدًا أو إقرارات تصحيح بأثر رجعي.

قيد فريد لكل دورة حوالة ولكل حركة رجوع. مصدر العكس ونوعه وشحنته ومبلغه وعملته وتفاصيله السالبة الدقيقة تُفحص داخل قاعدة البيانات عند إغلاق المعاملة. تصحيح حالة أو قيد مخالف لا يتم تلقائيًا؛ يمنع الخادم الحركة عند اختلاف سجل النقد عن حالات التحصيل والصرف والرجوع.

الخروج أو تأكيد الوصول مع الحالة والإصدار والقيدين والتدقيق ونتيجة منع التكرار ذري. فشل القيد الثاني أو سجل التدقيق يعيد كل الآثار، بما فيها إثبات الاستلام ونتيجة الأمر. لا تعديل أو حذف للقيود والأحداث المالية الأصلية أو العكسية.

## القراءة والواجهة

GET /api/cash يبقى ضمن نطاق الدور والملكية، مع حقلي remittanceCount وremittanceReturn للصف؛ الثاني يعرض الطلب الفعال فقط. صفوف العهدة المفتوحة والرجوع المعلق لها أولوية العرض، والإجماليات تشمل كل النطاق قبل حد 50 صفًا.

- receivedMinor: مجموع استلامات العمليات التاريخية، بما فيها حوالة صُححت ثم استُلمت مجددًا.
- netRemittedMinor: صافي الحوالات بعد عكس ما رجع إلى المحصل.
- remittanceReturnTransitMinor: نقد خرج إلى المحصل ولم يؤكد وصوله بعد؛ هو جزء من صافي الحوالات وليس رصيدًا إضافيًا.
- operationsBalanceMinor: النقد المتبقي فعليًا في خزينة العمليات بعد خروج نقد الصرف أو رجوع الحوالة.
- heldMinor: نقد أكد المحصل حيازته ولم تستلمه العمليات بعد.

واجهة «التحصيل وعهدة النقد» تعرض مراحل الرجوع بأزرار بحسب الدور، وتوضح أثر كل إقرار، وتطلب المبلغ والمرجع والسبب ومراجعة قبل الحفظ. لا تُتاح إقرارات العمليات للمحصل. توضح الواجهة الفرق بين الإجمالي التاريخي والصافي والعهدة، وتعرض رقم الحوالة بعد تكرار الاستلام.

عند فقد الرد تجمد الحقول وتعيد الأمر والمفتاح نفسه داخل الصفحة المفتوحة. الخادم يحمي من التكرار بعد إغلاق الصفحة أيضًا، لكن استعادة نموذج الأمر المعلق بعد إغلاق التبويب ما زالت لاحقة.

## أدلة التحقق والحدود

tests/cash-returns.test.ts يغطي المراحل الثلاث، واستقلال العهدة، ومنع صرف أثناء الرجوع ومنع رجوع نقد مرتبط بصرف متجر حتى استرداده فعليًا، والإلغاء قبل الخروج، والصلاحيات وعزل المحصل والمبالغ والإصدار ومنع التكرار، والنقطة والمندوب، وذرية القيدين والتدقيق، واستلام حوالة ثانية دون إعادة تحصيل العميل، وترقية الإصدار 15 والاستمرار بعد إعادة التشغيل. أدوات ترقية اختبارات الصرف السابقة تعيد مخططها السابق في قواعد معزولة فقط.

scripts/cash-return-check.ts يختبر الإقرارات الثلاثة واستلام حوالة ثانية وفقد الرد بعد الحفظ في كل مرحلة، ومطابقة الرصيد وعدم تكرار تحصيل العميل، وأحجام 1440 و390 و360px. scripts/cash-check.ts يفحص رحلة التحصيل السابقة. بيانات الاختبار منفصلة عن قاعدة العرض الدائمة.

الرد الجزئي، وإعادة تعيين المحصل أو تحويل العهدة إلى حساب آخر، وحل فقد نقد الرجوع أو توثيق فرق وصوله، والموافقات المالية الإنتاجية، وتعدد الخزائن والعملات، وتصحيح مبلغ تحصيل العميل أو رد ماله، وتوزيع الرسوم وأجور الشركاء والمطابقة البنكية وأحداث المالية للتطبيقات لاحقة. عند نقص النقد يبقى الرجوع مفتوحًا؛ لا يوجد شطب أو إغلاق جزئي. لا تُغلق بوابة المالية بهذه الشريحة.

نتيجة التحقق: 109 اختبارات ناجحة للمشروع بالكامل، والبناء وفحص التنسيق ورحلة التحصيل السابقة ورحلة رجوع الحوالة في المتصفح. أُعيدت اختبارات الرجوع بعد تشديد مطابقة عداد الحوالات ومصدر طلب الرجوع الحالي، ونجحت. روجعت لقطة الهاتف بصريًا؛ لا يوجد تجاوز أفقي.

أُعيد تشغيل العرض المحلي بترحيل 16. نجحت قراءة التحصيل والصرف مع مطابقة سليمة، ورصيد الخزينة وصافي الحوالات وعهدة الرجوع صفر. لم تُضف بيانات الاختبار إلى القاعدة الدائمة.

تحديث لاحق: أُضيفت [استعادة إقرارات لوحتي التحصيل والصرف](./FINANCIAL-COMMAND-RECOVERY.md) بعد إغلاق التبويب، وفحص نتيجة دون تكرار حركة، وإعادة الإقرار نفسه بعد مراجعة. النص السابق عن حدود حفظ الإقرار يعكس حالته عند تنفيذ الشريحة الأصلية؛ استعادة تحصيل النقد المرافق لتسليم الشحنة وباقي الأوامر تبقى لاحقة.

# عرض خاص مستضاف — Render وNeon

هذه بوابة عرض ببيانات اصطناعية، وليست تسجيل دخول إنتاجياً أو ربطاً حياً بتريند سي. يحتفظ التشغيل المحلي بـPGlite وقاعدته الحالية؛ وضع `APP_MODE=hosted-demo` يستخدم قاعدة Neon مستقلة. لا تُرفع ملفات `.local` أو أسرارها إلى Git.

## التنفيذ

- يشترك المحركان في `initializeDatabase` والترحيلات الأصلية حتى 31 دون إعادة كتابة الجداول أو إسقاطها. تهيئة Neon تنفّذ داخل معاملة واحدة، وتفشل ذرياً عند أي خطأ.
- موصل Neon الرسمي يستعمل WSS المشفّر مع معاملات تفاعلية على اتصال واحد. فحص TCP المباشر من هذا الجهاز أعيد ضبطه، بينما نجح الاتصال المشفّر عبر HTTPS وWebSocket. [وثائق الموصل الرسمي](https://neon.com/docs/serverless/serverless-driver).
- المعاملات المركّبة تمسك قفلاً استشارياً على مستوى قاعدة البيانات، بما يشمل فترة تداخل نسختين أثناء النشر. هذا يحافظ على تسلسل الأوامر الحالي؛ لا ندّعي أنه بديل تصميم إنتاجي عالي التوازي. حجم pool ثلاثة اتصالات.
- بوابة العرض تحمي الواجهات وAPI، مع رمز خاص وكوكي HTTPS آمنة ومهلة ثماني ساعات وحد محاولات وتحقق من أصل نموذج الدخول. تبديل الأدوار متاح داخل العرض المحمي فقط. الاتصالات الداخلية تحمل سراً لا يصل إلى الواجهة. مسار `/api/health` عام ويفحص القاعدة دون إظهار بيانات.
- أصل HTTPS مطلوب، وكذلك مفاتيح تطبيق وwebhook ثابتة ورمز دخول قوي. لا يوجد رجوع صامت إلى قاعدة مؤقتة عند نقص إعداد الاستضافة. تُخفى تفاصيل أخطاء الاتصال وSQL عن سجل بدء التشغيل.

## إعداد الخدمة

المتغيرات موضحة بقيم وهمية في `.env.example`. تُحفظ القيم الحقيقية في Render فقط ونسخة محلية مستبعدة من Git. أوامر البناء والتشغيل: `npm ci --include=dev && npm run build` و`npm start`. مسار الصحة `/api/health`. البناء الحالي عادي على Render؛ لا حاجة لصورة Docker لمعالجة خطأ اتصال قاعدة البيانات.

بيانات العرض الحالية في Neon Frankfurt. خدمة Render الموجودة في Oregon؛ الاتصال عابر للمناطق وقد يزيد زمن الاستجابة. نقل خدمة العرض إلى Frankfurt تحسين لاحق إذا أثبت القياس الحاجة، ولا يتطلب نقل قاعدة المستخدم المحلية.

حد V8 heap المحلي 256MB ليس حد إجمالي RSS. يجب متابعة حالة خدمة Render وذاكرتها فعلياً. قد تتأخر أول زيارة بعد السكون في الخطة المجانية، وتبقى البيانات على Neon عند إعادة تشغيل خدمة الويب.

## التحقق قبل النشر

نجحت مجموعة الانحدار المحلية: 177 اختباراً دون فشل (`artifacts/hosted-full-tests.txt`)، واختبار إضافي لبوابة العرض (`artifacts/hosted-gate-tests.txt`). نجح البناء وفحص الأنواع والتنسيق. نجح اختبار قاعدة Neon الفعلية: الترحيلات، rollback، عدم تكرار seed بعد إعادة الفتح، تسلسل اتصالين، وقراءة API (`artifacts/neon-integration-check.txt`). نجح تشغيل `server/main.ts` مع Neon وبوابة العرض والواجهة المبنية وجلسات العميل والعمليات (`artifacts/hosted-main-smoke.txt`).

تشغيل فحص القاعدة الآمن: `node --env-file=.local/hosting.env --import tsx scripts/neon-check.ts`. لا يطبع كلمات المرور، ولا ينظف بيانات التشغيل. نتيجة الرابط المنشور تُوثق بعد اكتمال النشر؛ نجاح هذه الفحوص لا يعني وحده أن Render أصبح Live.

# ساعات نقاط الاستلام — ترحيل 28

## السياسة

يُحسب الدوام على الخادم بتوقيت `Asia/Damascus`، بصرف النظر عن توقيت جهاز العميل أو الخادم. الدوام إما مستمر 24 ساعة، أو جدول كامل للأيام السبعة. اليوم يمكن أن يحتوي فترتين كحد أقصى مع استراحة بينهما، أو يكون مغلقًا. بداية الفترة مشمولة ونهايتها غير مشمولة، والدقة دقيقة واحدة. `24:00` نهاية صالحة فقط. الدوام الذي يتجاوز منتصف الليل يقسم إلى فترتين على اليومين المعنيين؛ لا تُخمن نية فترة مقلوبة.

استثناء التاريخ يحل محل يومه كاملًا، سواء بالإغلاق أو بفتح فترات إضافية. التاريخ وفق دمشق، وليس UTC. لا يُقبل تاريخ مستحيل أو يوم مكرر أو فترات غير مرتبة أو متداخلة. حد الاستثناءات 90 تاريخًا للنقطة في هذه الشريحة، مع سبب محفوظ في التدقيق. لا تعاد استثناءات السبب الإداري إلى قوائم العميل.

المفتاح السابق `pickupEnabled` يبقى مستقلًا: يوقف الطلبات الجديدة. الدوام يحدد متى تعمل النقطة. استمرار الدوام لا يلغي تعطيل استقبال الطلبات يدويًا. المواقع القديمة تهاجر إلى دوام مستمر كي لا تُخترع لها ساعات لم يعتمدها المشغل؛ يجب ضبط ساعاتها الفعلية قبل التشغيل.

## التحقق والعهدة

- القائمة العامة للعميل توضح النقاط المفتوحة والمغلقة؛ المغلقة لا يمكن اختيارها. قائمة الأقرب تستبعد المغلقة قبل ترتيب واختيار الخمس. قياس القرب ما زال مسافة مستقيمة تقريبية، وليس زمن طريق.
- إنشاء عرض الخدمة يراجع الدوام والسعة. تأكيد الطلب يراجعهما مجددًا داخل المعاملة نفسها؛ تغيير الساعة قد يغلق النقطة حتى دون تغيير إعداداتها.
- تعديل الجدول يزيد إصدار الموقع؛ العرض السابق لا يُستهلك بإعدادات قديمة ولو بقيت النقطة مفتوحة. إعادة أمر طلب سبق تأكيده تعيد نتيجته بدل إنشاء طلب جديد، حتى إن أغلقت النقطة لاحقًا.
- وصول المندوب لا ينقل العهدة. عند الإغلاق يُرفض `receive_pickup`؛ يبقى الطرد مع المندوب وتبقى سعته مشغولة. يمكن توثيق الوصول نفسه أو اتخاذ مسار الإرجاع الموجود دون اختلاق استلام.
- إذا أغلقت النقطة بعد تسلم الطرد، تبقى العهدة معها. لا يُمنع تسجيل تسليم فعلي للعميل برمزه أو تسليم فعلي لمندوب إرجاع مخوّل. الدوام لا يلغي الطرد ولا يحرر سعته ولا يشطب عهدته تلقائيًا.
- مهلة استلام العميل الحالية تبقى 72 ساعة تقويمية من الاستلام؛ لا تحتسب «ساعات عمل» في هذه الشريحة. يجب إبلاغ التشغيل بهذه السياسة وعدم عرضها كـ72 ساعة دوام.

## API والصلاحيات

`GET /api/network/pickup-sites/:id/hours` متاح للعمليات وموظف النقطة نفسها. يعيد `{id,version,schedule,status}`. حسابات المتاجر والمندوبين والمكاتب لا تقرأ تفاصيل الجدول الخاص من هذا المسار؛ الحالة العامة متاحة بحسب صلاحيات مواقع الشحنات وقوائم العميل.

`PUT /api/network/pickup-sites/:id/hours` متاح للعمليات فقط، مع جلسة و`Idempotency-Key`:

```json
{
  "expectedVersion": 1,
  "schedule": {
    "mode": "always",
    "days": [],
    "exceptions": [
      { "date": "2026-12-25", "intervals": [], "reason": "عطلة رسمية" }
    ]
  },
  "reason": "تحديث ساعات النقطة"
}
```

للجدول الأسبوعي `mode=weekly` و`days` سبعة عناصر مختلفة؛ `day=0` الأحد حتى `day=6` السبت، و`intervals` من صفر إلى فترتين `{start:"09:00",end:"18:00"}`. لا يوجد توقيت يرسله المستخدم لتجاوز قرار الخادم.

الحفظ وسجل `network_audit` وتسجيل نتيجة منع التكرار ذرية. إذا فشل التدقيق يعود الجدول وإصداره معًا. اختلاف الإصدار يرفض الكتابة بدل طمس تعديل آخر؛ إعادة المحتوى والمفتاح نفسيهما تعيد النتيجة السابقة.

`GET /api/storefront/pickup-sites` يعيد النقاط المفعلة مع `openingStatus` دون استثناءات إدارية. جلسة المتجر وقائمة الأقرب و`Bootstrap.sites` تتضمن الحالة أيضًا. الحالة تضم `openNow,timeZone,localDate,localTime,label,closesAt`. هي قراءة وقتية وليست ضمانًا لساعة وصول لاحقة. تعرض الواجهة تحديثًا كل 30 ثانية أثناء ظهورها، والخادم يعيد التحقق دائمًا. لا تُضمن أهلية السعة من مجرد ظهور النقطة بالقائمة.

خطأ الإغلاق `PICKUP_CLOSED` (409)، وخطأ تغير إعدادات العرض `QUOTE_SITE_CHANGED`، مع عدم حجز مخزون أو استهلاك العرض عند الفشل.

## الواجهة والتجربة

من شبكة الشركاء افتح «ساعات العمل» للنقطة. اختر دوامًا مستمرًا أو جدولًا أسبوعيًا، أو قالب 09–18 والجمعة عطلة. عطّل يومًا بزر اختيار، وعدّل الوقت بمنتقي الساعة. يمكن إضافة فترة ثانية أو نسخ دوام الأحد لباقي الأيام. للإغلاق اختر تاريخًا وأضف استثناء؛ ولدوام استثنائي فعّل فتراته. الحفظ لا يعدّل عنوان النقطة أو سعتها.

حساب موظف النقطة يعرض جدوله واستثناءاته للقراءة، وحالة الإغلاق تظهر في تفاصيل الشحنة. تعديل الجدول مسؤولية العمليات. بيانات الاختبار في الذاكرة أو مجلدات معزولة تحت artifacts؛ لا تُعدّل قاعدة بيانات تجربة المستخدم.

## أدلة التحقق

اجتازت النسخة 155 اختبارًا عامًا دون فشل، وسبعة اختبارات للدوام ضمنها. تغطي المجموعة وقت البداية والنهاية والاستراحة والجمعة والاستثناء ومنتصف الليل بتوقيت دمشق، والتحقق من البيانات والصلاحيات والإصدار ومنع التكرار، وفشل التدقيق، وإغلاق النقطة بين العرض والتأكيد، وعهدة المندوب وتسليم عهدة موجودة، والترحيل وإعادة التشغيل.

نجح البناء وفحص الأنواع والتنسيق. ينفذ `node --import tsx scripts/pickup-hours-check.ts` حفظ الجدول والاستثناء ومنع العميل من اختيار المغلقة وقراءة الموظف دون تعديل، ويفحص خمسة عروض شاشة دون تجاوز عرض الصفحة. كل بياناته معزولة؛ لا يغير قاعدة تجربة المستخدم.

## الحدود التالية

حجز موعد وصول مستقبلي، ضمان الوصول قبل الإغلاق، تقويم العطل الوطني الآلي، وإعادة احتساب مهلة الاستلام بساعات العمل ليست منفذة. لا تُستنتج هذه القدرات من ظهور الجدول. إدارة النزاعات ومسؤول المتابعة والتصعيد والقرار المدقق هي الدفعة التالية، ولا تُغلق جميع السياسات التشغيلية بإضافة الساعات.

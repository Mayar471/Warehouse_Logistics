# المنصة اللوجستية المستقلة

الشريحة البرمجية الأولى: واجهة عربية احترافية وAPI فعلي وقاعدة PostgreSQL تجريبية دائمة، لتنفيذ رحلة طرد محلي قبل ربط Tendsy.

استعادة 18 أكتوبر: أُلغيت تغييرات محاولات الاستضافة التي كسرت عقد القاعدة ووصلات الميزات، مع استبقاء تطوير الصرف والنزاعات والساعات والأولوية والترشيح. النسخة الحالية محلية؛ [تقرير الاستعادة وخطة المحاولة المجانية التالية](./docs/RESTORE-AND-HOSTING-2026-10-18.md). لا تُنشر حسابات العرض المفتوحة على الإنترنت بهذا الإعداد المحلي.

## التشغيل

تحديث 18 أكتوبر: أضيف صرف أجور الشركاء وبوابة مكتب التوصيل محليًا. [العقد وتجربة الواجهة والحدود](./docs/PARTNER-PAYMENTS.md)، و[ترتيب مراحل الإغلاق](./docs/RELEASE-ROADMAP-2026-10.md). أضيفت [ساعات النقاط والإغلاقات الاستثنائية](./docs/PICKUP-HOURS.md) في ترحيل 28، مع سياسة واضحة لحماية العهدة الموجودة.

ترحيل 29 يضيف [المتابعات والنزاعات](./docs/DISPUTES.md) بأطراف وصلاحيات ومسؤول ومهلة وإشعارات وقرار واعتراض وإغلاق، دون تعديل النقد أو العهدة تلقائيًا. الخطوة التالية هي أولوية الطلب والإسناد المحسّن ثم تجهيز الإنتاج.

يتطلب Node.js 24.11 أو أحدث؛ النسخة المختبرة 24.11.0. لا يحتاج العرض إلى Docker أو خادم قاعدة بيانات خارجي.

```powershell
git clone https://github.com/Mayar471/Warehouse_Logistics.git
cd Warehouse_Logistics
npm ci --offline=false
npm run build
npm run demo
```

افتح [العرض المحلي](http://127.0.0.1:3001). يبقى الأمر قيد التشغيل؛ Ctrl+C يوقفه. لا حاجة لإعادة التثبيت عند التشغيل التالي.

لرحلة العميل افتح [المتجر المؤقت «تريند سي»](http://127.0.0.1:3001/shop): تصفح ← تفاصيل المنتج ← سلة ← عنوان ← عرض توصيل ← تأكيد ← طلباتي. افتح لوحة العمليات في تبويب آخر لإسناد الشحنة وتنفيذ رحلة المندوب، ثم شاهد الحالة تتحدث لدى العميل. لا يؤثر اختيار حساب العمليات على جلسة المتجر.

تفاصيل تجربة العرض والتحقق في [تجربة المتجر المؤقت](./docs/STOREFRONT-DEMO.md).

للتطوير مع تحديث الواجهة تلقائيًا:

```powershell
npm run dev
```

الواجهة على [127.0.0.1:5173](http://127.0.0.1:5173)، والخادم على 3001. اختر إحدى الطريقتين، لأنهما تستخدمان منفذ API نفسه.

## رحلة عرض أولى

1. افتح حساب مدير العمليات الافتراضي، وراجع المؤشرات والشحنات.
2. أنشئ شحنة: اختر المتجر، واسمًا اصطناعيًا وعنوانًا يحتوي دمشق، ثم اعرض الخدمة وأكد التنفيذ.
3. افتح الشحنة وأسندها إلى مندوب ذي سعة مناسبة.
4. انتقل إلى حساب المندوب المكلف واقبل المهمة، ثم إلى حساب المتجر صاحب الطرد وأكد تجهيزه وتسليمه إلى المندوب المحدد. عد للمندوب وأكد استلام الطرد وابدأ التوصيل. لطلب منشأ من المتجر، افتح «طلباتي» لدى العميل وأظهر رمز الاستلام وأدخله لدى المندوب؛ أما الشحنة اليدوية فتستخدم إقرار التسليم التجريبي. الطلبات الجديدة تتطلب تأكيد المنشأ؛ بيانات العرض السابقة موسومة كحالات سابقة.
5. عد للمشغل أو المتجر وتحقق من الحالة والخط الزمني ورابط العميل قليل البيانات.
6. في مختبر التكامل أوقف المستقبل، ونفذ إجراء، ثم استأنفه وأعد محاولة المعلق للتحقق من التعافي.
   استخدم مرشح «الفشل النهائي» لإعادة تشغيل حدث توقف بعد إصلاح السبب؛ تتطلب العملية سببًا ويظهر أثرها في سجل التدقيق. شاشة المطابقة تكشف الحالات المفقودة والمتأخرة وتتيح إرسالها مجددًا. التفاصيل في [المطابقة والتعافي](./docs/INTEGRATION-RECOVERY.md).
7. اختبر الإلغاء قبل الاستلام أو تعذر التسليم ثم مسار الإرجاع بعد الاستلام.

لرحلة نقطة الاستلام، اختر «الاستلام من نقطة قريبة» في المتجر. بعد وصول المندوب انتقل إلى حساب «موظف نقطة الروضة» وأكد استلام الطرد، ثم أظهر الرمز في «طلباتي» لدى العميل وأدخله لدى موظف النقطة. تُوثّق المهلة والسعات والإرجاع في [مسار نقاط الاستلام](./docs/PICKUP-POINTS.md).

من «شبكة الشركاء» يستطيع مدير العمليات إضافة نقطة استلام وإدارة سعتها واستقبالها بسبب مسجل. تظهر النقاط المفعلة للعميل بعد إعادة تحميل المتجر، ولكل نقطة حساب موظف عرض محدود بها. راجع [إدارة الشبكة](./docs/NETWORK-MANAGEMENT.md).

كل حساب يعرض نطاقه الفعلي من الخادم. تغيير حساب العرض يدخل حسابًا تجريبيًا مخصصًا؛ لا يغير صلاحية مستخدم إنتاجي.

## ما تم تنفيذه

- لوحة عمليات وتصميم RTL وخط عربي محلي، وصفحات شحنات وشبكة ومندوب وتكامل وتتبع.
- إنشاء عرض وطلب عبر خادم تطبيق تجريبي يستخدم API المنصة.
- صلاحيات متجر ومندوب ومشغل، وحدود وصول على الخادم.
- آلة حالات وقبول مهمة وعهدة وإلغاء قبل النقل وإرجاع بعده.
- تحقق الإصدار، ومنع تكرار الإنشاء والأوامر، وفحص سعة المندوب في معاملة.
- تاريخ وأحداث outbox دائمة وإرسال HTTP محلي موقّع وإعادة محاولة ومستقبل يمنع التكرار والتراجع إلى إصدار قديم.

## البيانات والحدود

البيانات الاصطناعية تُبذر مرة واحدة. البيانات الدائمة في `.local/postgres`، ومفاتيح التطبيق والتوقيع في `.local/secrets.json`، وكلاهما مستبعد من التتبع. تعاد الجلسة عند إعادة تشغيل الخادم.

الخادم مرتبط بالمضيف المحلي فقط. أضيف مخزون محلي: حجز وتجهيز وخروج ووارد وعزل مرتجع وفحص كامل أو جزئي وجرد ومطابقة ومواقع مملوكة بأرصدة مستقلة ونقل محلي بينها بعهدة واستلام فعلي. طلبات تريند سي تختار موقعًا مؤهلًا يملك كامل السلة. التخزين المشترك وتصحيح قرارات التسوية والمطابقة الخارجية والمصادقة الإنتاجية وتوزيع أجور الشركاء وتصحيح التحصيل والرد الجزئي والإلكتروني والنقل بين المدن وH3 والتحسين وموصل Tendsy ما زالت لاحقة. نقاط الاستلام وتأكيدات المنشأ تعمل محليًا؛ قنوات الإثبات الإنتاجية لاحقة. خريطة لوحة الملخص توضيحية؛ خريطة موقع المندوب الجديدة تعرض قراءة GPS مشارَكة أثناء التوصيل دون حساب طريق. طلبات المتجر تستخدم رمز جلسة العميل؛ الشحنات اليدوية تستخدم إقرارًا تجريبيًا.

لا توجد رسائل أو أموال فعلية. عرض أسعار SYP اصطناعي ولا يشير إلى رسوم تجارية معتمدة. لا تنقل هذا الإصدار كما هو إلى تشغيل عام؛ أكمل بوابات الخطة المرتبطة بالخدمات الفعلية أولًا.
